# H3 异能下一轮优化方案

日期：2026-10-08。状态：方案待执行，本轮未制作新提示词或渲染 JSON。

> 执行者按任务逐项推进，沿用 executing-plans 的检查方式。当前只编制方案，不启动子代理，不调用接口，不提交渲染。

**目标：** 保留本轮获认可的局部表现，先验证动作时机和运动轨迹，再处理细节与复杂打斗；将经出片复核的结果逐步纳入 h3-power-fx 的有边界参照。

**方法：** 原版和候选使用同配置、同种子对照；诊断候选只改变一个目标因素。需要重新编排的复杂动作单列为新设计，不能混称单因素修复。

**工具：** 已有 Director schemaVersion 5 JSON、h3-shot-prompt 的提示词检查器、h3-director-json-review 的 JSON 检查器，以及用户云端渲染。所有 .py 和主 skill 规则保持原样。

## 1. 路线选择

| 路线 | 收益 | 局限 | 本方案安排 |
|---|---|---|---|
| 先修两个核心动作链，再逐项扩展 | 工作量可控，能找出改动是否有效 | 需要分轮反馈 | 推荐 |
| 一次重写全部 12 个情节 | 能快速看整体新版本 | 成本高，多个因素同时变化，难知道哪项有效 | 暂不采用 |
| 再批量调用官方改写 API | 能增加官方文体样本 | 不能直接回答本地停顿、穿模、受力及跨镜保持问题 | 本轮不安排 |

现有证据为用户口述，尚未直接查看视频。依据见 RENDER_FEEDBACK_4.md/.json/_user.txt 和配置补充。A1/A2 与文件的对应仍按前四段顺序推定；A3 和声音未反馈。不能从本轮计算整段成功率，也不能归因于 BF16 或20步。

## 3. 第一轮：10 段、80 秒，先验证 C1 和 B3

每版本两个原种子：2026100801 / 2026100802。两类场景都是8秒，按24fps为192帧；标准第一轮共10段、80秒。

| 版本 | 段数 | 改什么 | 保留什么 | 主验收项 |
|---|---:|---|---|---|
| C1 原版对照 | 2 | 不改原提示词 | 原生成字段 | 本轮原配置下是否仍出现接近后站等 |
| C1-T 接敌节拍 | 2 | 只改接敌动作块：女子在打手到达接触距离前进入预备姿态；打手最后一步与能量命中位于同一动作节拍 | 原镜头切点、时长、人物、能量与撞柱结果、声音段 | 打手持续进攻，没有停好再挨打；女子在合理距离拦截，原特效不退步 |
| B3 原版对照 | 2 | 不改原提示词 | 原生成字段 | 缺响指、杯子回升是否复现 |
| B3-H 触发可见性 | 2 | 只改右手响指的可见姿态与动作描述 | 原杯子下落/定高描述、镜头、两人一杯、声音 | 画面看见手指完成响指；杯子和外卖员分别记录，不因响指成功就整段通过 |
| B3-P 杯子定高 | 2 | 只改杯子轨迹描述：下落中途停止，以外卖员手与路面为位置参照，保持停止后的同一高度 | 原响指描述、镜头、两人一杯、声音 | 杯子确有先下落，然后停止；没有上升回送、落地或换杯；触发是否成功另外记录 |

C1-T 调整的是完整接敌节拍，不把姿态前置与最后一步同步拆称两个已证实的词语规则。C1 保留原1.7/3/4.5/6秒切点；若该节拍在原切点下无法承载，另外提出“改切点”的第二候选，不能顺手改完后仍声称只改动作文字。

B3-H 与 B3-P 都从同一个原版派生，彼此不叠加。若两者分别解决对应问题，再制作合并候选用原两种子测试；这一步额外2段16秒，不计入首轮80秒。合并后仍须同时验收触发、杯子定高与外卖员姿态，不能自动认定组合成功。

若能核对旧四段与新候选的完整配置、有效提示词相同，可以复用旧原版，只生成6段48秒；没有配置元数据时建议保留标准10段的新对照。即使重新跑原版，同种子也不保证跨工作流完全一致，需记录工作流版本及实际参数。

## 4. 第一轮结果如何决定下一步

| 观察 | 后续处理 |
|---|---|
| C1-T 两段都改善，特效和结果保持 | 作为暂可用候选；再用两个新种子检查能否复现，之后才推广到其他接敌戏 |
| C1-T 只一段改善 | 标为种子敏感，不宣布稳定；先看失败段的最后一步和接触镜是否清楚 |
| B3-H 响指清楚、杯子仍回升 | 触发可见性有所改善，轨迹仍待修；不把二者捆绑为成功 |
| B3-P 杯子定高、响指仍缺失 | 轨迹有所改善，触发仍待修；等待两项合并候选验证 |
| 同配置原版这次不复现旧问题 | 原先差异尚不能单独归因于提示词；保留原版与候选结果，不靠一轮选择“最好种子” |
| 候选无改善，或出现新问题 | 保留失败记录；看对应视频/生成元数据后换一个假设，不不断加形容词 |

新种子回归安排在候选值得保留之后，每情节再用两个新seed，并记录具体值。两个原种子是与旧样本对应的修复检查，新seed是后续重复性检查；两者均不足以给出稳定成功率。

## 5. 第二轮：一次两项，先手势和照明

第一轮反馈到达后再定实际批次，不一次制作全部候选。每个候选先用原两个种子；需要原版对照时加入同配置的两段原版。

| 优先级 | 问题 | 最小测试 | 验收 |
|---|---|---|---|
| 1 | A2 施法手势 | 只补用户指定的双指并拢、拇指与无名指接触；小指姿态不擅自升级为硬规则 | 手势清楚且解剖合理，叶流/门的原动作不受损 |
| 1 | A4 照明不足 | 保留电弧来源/握拳/白烟，只调整电弧造成的局部照明反差描述；先不改环境光和镜头 | 电弧出现时脸与洞壁有可见变化，握拳后相应照明结束 |
| 2 | A4 头发不落 | 在照明测试之外，单独限定由电荷带动的几缕发丝随握拳落定 | 头发变化与电弧结束相关，不能仅有普通持续风吹 |
| 2 | A1 鼻血 | 单改血迹来源和外观：鼻孔边缘起始的短小红色痕迹 | 看起来来自鼻孔，不像从嘴流出 |
| 2 | A1 水面/落杯水花 | 保留落杯与溅水结果，单独调整落杯受力描述，先不改杯子高度、景别或删水花 | 水面随杯子运动，落杯与溅水方向/幅度可信；若需改变高度另立候选 |
| 2 | B2 雾色、碎石、瞳光 | 三项各立候选，不合并改；先保留认可的环绕运动 | 白色云雾不变黑；碎石有重力落回；眼部光在瞳孔、短闪后恢复 |

A2 完整手势先在较清楚的单人场景验证，通过后再迁移到C2；迁移属于新场景验证，不能把A2的通过算成C2已通过。若原景别看不清指位，再单列景别候选，不同轮次同时改手势与景别。

## 6. B4 箭：三项逐步验证

1. **速度候选：** 保留原抓点和转角文字，只把入画阶段设计为快速、箭头领飞，冻结后保持清晰；验收真实飞行感、停点和端向。冻结不是慢速漂入。
2. **抓点候选：** 在已接受基线上只处理右手接触箭杆中段。验收拇指食指接触木杆，左掌仍维持，手与箭不穿模。
3. **终角候选：** 在接受的抓点基线上只处理旋转终点：箭头垂直指向地面、羽尾垂直向上；右手撤离后保持竖直，不停在约45度。

每步2种子，前一步未通过不把其改动默认为成功基线。逐步累积后要验收完整动作链。保留原8秒连续镜头；若时长或构图不够需另列方案，不能偷偷切镜、加时或删拨箭。

## 7. 复杂打斗先重编排，再测组合

这部分是新设计，不能算“只加一句话”。先验证接触，随后恢复完整人数和事件。

### C2：断刀与同一缕剑气连续

- 先隔离一次剑气斩刀：发出、可见命中、刀身仅断一次、残余刀身与刀柄在手、刀尖掉落。另测跨镜后断刀状态保持。
- 再规划松枝与能量路径的空间关系，使斩刀后的剩余剑气有可见连续出口，保留原断枝结果。不得让剑气已飞到阶梯下方后换镜重现于树枝。
- 简化诊断必须标明暂不测滚阶/断枝，不能冒充原完整情节；重组后另跑完整8秒场景。

### C3：六人受力与车门结果

- 接棍要由对手挥棍形成威胁；主角拦截在棍到身前的动作节拍里，不让杂兵站着供抓。
- 持刀者扑近、主角施力、对手离地/后移与撞车需连续；先解决C1同类接敌问题，再迁移验证。
- 车门凹痕在后续出现该车门的镜头继续可见；原伤痕保持作为独立候选。
- 用户目标是四人有击飞和重量感：先另做两人受同一次力量失衡、离地后落地的诊断，再测四人、最后整合一打六。两人测试不能记成四人或六人已成功。
- 群体结果从“膝先跪地”改为受力后的位移与落地，保留六名对手及前两人已有落点；不把杂兵消失、碎灰或自动跪拜当作降难度方案。

### C4：实体剑接触，再考虑剑影美感

- 先另做一剑、一个目标兵器的诊断：剑刃完全离鞘后转向 → 剑尖领飞 → 撞开兵器 → 对手有对应手臂/身体失衡 → 实体剑回原剑鞘。原一打十二JSON保留。
- 剑的出鞘与回鞘分别验收，不把种子2单次没有穿模视作普遍解决。主角用指诀控制；若设计握持则只能握柄，回剑抓剑身属于失败。
- 先在诊断中测实体剑，不将取消九道剑影伪装成原需求完成；实体剑接触成立后，再恢复九道半透明剑影并评价运动轨迹与构图。
- 完整十二人阶段为每次缴械写清目标和反应；其他人可以因看到攻击而退，却不能表现为未命中就受创。原稿只有四人缴械与八人退却，不擅自改成十二人中剑或死亡。

## 8. 反馈与验收方法

每段记录准确文件名/片段ID、种子、实际动作先后、目标项结果、原认可项是否退步、新问题、声音。未看清或未听留未评价，不能强制二选一。

- 画面项：触发可见、运动轨迹、接触与受力、人数/手/兵器、损伤保持、结束状态、自然度。
- 声音项：动作声音是否对位，是否符合原声源限制，静止段声场是否符合要求。画面通过不带过声音。
- 原版与候选对应同seed比较；两个种子分别记录，不以最好一段代表整个候选。
- 首轮优先取得C1/B3的对应短视频，尤其是失败候选；如只能口述则保留用户报告证据等级，不声称已逐帧确认。

## 9. 什么时候更新 skill

1. 原话、原JSON、参数、候选差异与每个种子结果先入档，失败样本同样保留。
2. 同原两个种子达到目标且原认可项不退步，候选可暂时用于该场景。继续用两个新种子检查重复表现。
3. 先把确有用户认可的完整提示词写入 h3-power-fx 的局部参照，注明场景、模式、配置、样本数和未验证范围；不要称稳定成功率。
4. 要提升为通用写法，还需在另一场景验证迁移结果。例如C1接敌时机改善不能自动证明C3持刀扑近也解决。
5. 更新前备份安装版，更新后核对仓库/安装包/安装目录一致；完成对应的 skill 检查。主 skill 与任何脚本的改动仍受 AGENTS.md 的具体文件授权限制。
