## Claude 的方法，哪些沿用

提供的粘贴记录属于第一轮出片之前：它查了覆盖情况、三个 skill 的互相矛盾和 lint 的误报漏报，然后让两个盲写手各写两条，再由独立裁判比较，最后修改、测试和打包。它的重要价值是可以追踪“原句—问题—修改—复测”，而不是复刻其中每一个修改命令。

这份旧记录的少切建议，后来已有第一、第二轮出片反馈修订。因此本轮从当前第二版开始，不用旧记录回退版本。审前仓库提交 `0ccc1d7f5b0aec48fc2c0e21d90ed5ff2c5d9c48` 的 15 份 skill 文件，与已安装第二版统一换行后全部相等；文件 SHA 差异仅来自换行。

本轮沿用并收紧：

1. 先冻结当前 skill 和盲写基线，再看新增说明的作用。写手不读取本批官方结果或另一阶段的输出。
2. 引文由程序核对存在性。独立审查的 74 条引用都能在简报、官方原文或审前 skill 中逐字找到；完整官方提示词复制自响应，12 条逐字相等。
3. 统计先说明口径。类型样本分母是同类两条，不把每类两条说成大量证据；用户明确意图与默认规则冲突时，修适用边界，不需要靠官方“多数票”授权改剧情。
4. 分别记录简报忠实度、文体/规则一致性、实际渲染效果。盲写通过只说明这几条请求更容易按要求写，不能说画质、物理或音画同步已改善。
5. 多处一起改的候选版只作整体对比。若要归因某条规则，另做其余文字不变的对照；保持旧版与各轮结果可追溯。

## 12 条官方文本的统计边界

原有 `analyze_ir.py` 未改动，运行输入为 `powers/cases.json` 与 `powers/results/`，输出在本目录。`features.csv`/`features.md` 是原脚本结果；本节补充人工核对，不回写原统计。

- 共 12 条成功 T2VA 改写；六类各都市、仙侠两条，每个需求只有一次采样，无参考图输入。
- 正文英文词数合计 3531，均值 294.25。计数用原脚本英文词正则，不把该均值变成每条写作目标。
- 显式 `[Shot N]` 标签共 30 个，均值 2.5；这不是可靠的实际镜头均值。`awaken_xianxia` 漏了第二镜标签，但在 00:07.500 明写转到面部特写。原脚本因此把它报告成单镜头。
- 12 条均无 lint ERROR；仍有 `MWS`、缺复指等 WARN，且 lint 没发现上述漏标签转场。0 ERROR 不能作为语义、镜头完整性或出片通过的证据。
- 10/12 条自加非 `N/A` 配乐；例外为 `telekinesis_urban`、`timestop_urban`。十二条简报均未要求配乐，这个频率只证明官方倾向自加配乐，不构成修改本地剧集默认 `N/A` 的理由。
- 声源封闭列表适用集合只有两条：`telekinesis_urban`、`timestop_urban`。前者官方新增落杯/水声，后者在冻结期间新增衣料/纸杯/液体声音。都要按简报复核，不能把“无配乐”当成已满足全部声音限制。

逐例空间、力度、手部占用、数量和结束状态偏差见 `EVIDENCE_AUDIT.md`。特别留意台阶上方被改为中部、门晃开被改成撞开、克制后退被改成惊慌后撤、灯闪烁被改成熄灭、微光剑影被扩写成强光与击飞。

## 接下来怎样学习

先用已有文本和具体出片问题迭代，不自动继续花钱采样。普通文戏、对话、快动作、异能和挂参考图的证据分别记录，不能跨类型直接推广。新增 API 仅在用户授权且现有样本无法覆盖具体问题时考虑。

优先验证时间冻结：比较同一提示词保留/删除全局表演段，使用同一配置和两个种子；只删这一段，不改变其他字。另附四条需求的第二版盲写/补充版盲写/官方三版整体对照，供后续检查能力链、人数、碰撞和声场；整体对照不能用于单句归因。JSON 只是静态检查通过，未导入、未渲染、未播放或听审。

渲染回报至少记录 JSON/提示词 hash、实际模型/精度、LoRA、采样设置、分辨率、seed、视频文件、原话反馈；评价完成度、方向/固定物、人数/身份、身体/道具、能力变化、声音限制与连续性。结果不足时保留“待测”，不写“已解决”。
