# H3 导播台 JSON 整体审查

处理**整个项目文件**（几十段），比如从 V7.3 导播台导出的 schemaVersion 5 JSON：检查、重写、再检查每一段，交回可以直接导入的 JSON。

和用户说中文。提示词默认英文；台词和画面文字保持原语言。

分工：
- `h3-shot-prompt`：**单段怎么写的标准。** 文体（可观察测试）、分镜、镜头头、运镜、动作、合法时长、台词预算、范例都以它为准。
- `h3-action-prompt-design`：补充手册。挂素材六段式、空间方向、门、手和道具、粤语、帧长、接力、病症对照表。
- `h3-seg-prompt-design`（用户本机）：从零规划一个项目。
- 本 skill：整份 JSON 的审查、批量重写和交付，出片前和出片后都用。

---

## 1. 硬规矩

- 只改每段的 `prompt` 和 `negativePrompt`。不改素材的 `path`、`alias`、`id`、`fingerprint`，不改镜头的 `id`、`seed`、`durationSeconds`、`latentRelay`、`secondSamplingMode`、`enabled`、`disabledAssetIds`。看着不对就标出来，不动手。
- 每个 `{{ref:别名}}` 原样保留、只出现一次、保持原顺序。
- 台词只在用户要求时改字。统一标点可以，但要报告。
- 每次交付都是**新文件**，带说明性后缀（`_新文体重写`、`_方向修正`）。上一版留在 scratchpad 里，方便对比台词和结构。
- 不保证渲染效果。只说提示词改了、还没测，等用户跑出来再判断。
- 异能段先核对用户指定的能力、人数、受力结果、一镜到底和声音限制。风险报告可以建议替代设计，重写时不静默把打飞改成踉跄、真人改成碎灰、念力开门改成人手开门；详见 `h3-shot-prompt/references/powers-and-effects.md`。

---

## 2. 读文件

schemaVersion 5 结构：
- `project {id, name, runId}`、`defaults {fps, baseSeed}`、`promptPrefix`、`promptSuffix`
- `continuity {mode: h3_av_latent, videoContextFrames, audioContextFrames, durationMode}`
- `assets[]`：`id, alias, kind, path, enabled, fixed, fixedOrder, shotIds[], includeVideoAudio, durationSeconds, audioDurationSeconds, fingerprint`
- `shots[]`：`id, title, prompt, negativePrompt, durationSeconds, enabled, latentRelay, secondSamplingMode, seed, disabledAssetIds[]`

每一段核对三组是否一致：提示词里引用的别名、启用且没被禁用的素材、`shotIds` 包含这一段的素材。不一致就报告，不悄悄修。

## 3. 流程

### 第 0 轮：脚本盘点（先量，再判断）

先跑脚本：`python3 scripts/lint_json.py 项目.json`。它对每个启用的段调用 `h3-shot-prompt` 的 `lint_prompt.py`（按该段 `durationSeconds`），列出 ERROR 和 WARN，并给一张全片汇总表。然后人工量脚本查不了的：

- 格式：挂素材的是不是六段式、顺序对不对；不挂素材的是不是三段式。（脚本查）
- **文体**：有没有不能通过"可观察测试"的句子——`IMPORTANT`、`FORBIDDEN`、括号状态标签、全大写运镜和动词、区间镜头头、`Line lands about`、`Total runtime`、`hard cut to`（改成 `the camera cuts to`）、给人看的规则段。（脚本查大部分，规则段要人工看）
- **镜头数和时长**：先判断每段是哪类戏，再对照 `h3-shot-prompt` 的镜头数表（快动作 8 秒 4–6 镜、15 秒 6–9 镜；多节拍文戏 15 秒 4–7 镜；对话戏 15 秒 2–6 镜；连续移动加运镜和安静戏 1–2 镜，优先一镜到底）；快动作每镜至少 1.0 秒，其余至少 1.5 秒，最后一镜至少 1.5 秒；两个角色交互（扫开、拦截、抓住、踩住）放进一个 1.0–1.5 秒的短镜头，从起跳或冲刺的最后一步开始，接触落在这一镜里；有移动的镜头写了往画面哪边动、关键固定物写了在画面哪一侧；切点小于实际片长，并且落在节拍边界上（换说话人、起因切到后果、后果切到反应脸）。标出一个镜头里并行了两条动作链的段。每个切镜句有没有写景别和运镜状态；后续镜头第一次提到前面的人和道具时有没有写 `from Shot N`。
- 每个镜头的主动作链数（超过一条就标）；每个物理接触有没有写全"起因 → 用力 → 反应 → 落定"；有没有命中 `h3-shot-prompt` 的"H3 做不好的事"。
- 要一路记住的状态（火、伤、湿、门、灯、手里的东西）有没有在每个相关镜头里用陈述句写出来。
- 最后一秒有没有新动作；最后一个事件落在全片哪里（都挤在前半段，尾巴会僵）。
- 实际片长：`durationSeconds` 按 17k+5 帧取整（比如 10 秒实际 10.13 秒）。（脚本查）
- 台词：语言标签、每段字数（对照 `h3-shot-prompt` 台词预算：10 秒 20–28 字，12 秒 28–36，15 秒 36–44，最多 48，动作多再少两成）、`<d>[语言] ` 标签后有没有空格、说话人编号（第一次出场就挂编号和 `on-screen`）、画内说话人说完有没有写收口、看得见脸的听者在三种情况下有没有写闭嘴（看不到脸的听者、没人说话的镜头不该写）、每个镜头几个人说话、每段几个声源。
- 跨段重复的句子（电影感底座、本场光源句、项目画风开头、全局表演段、字幕防护句、单声源句和声线段按各自适用范围照抄重复；时间静止、集体定身段不补全局表演段；其他通用规则段不应该）。
- 内部编号和制作备注：镜头 ID、P1 / FAN_A 这类地点代号、声线代号、"post""latent""为了接力"。
- 正向里的"没有 X"（"no subtitles""without a second person"）和缺席角色的名字。
- 每个挂上的素材：主体行有没有写明提供什么、不提供什么；角色卡有没有被挂在手、鞋、道具的特写上；纯色底的角色卡旁边有没有场景主体。
- negativePrompt 是否被复用；V7.3 没接这个口时应为空。

字数按 `h3-shot-prompt` 的预算（固定段——电影感底座、光源句、全局表演段、项目画风开头——不计入；其余单镜头 150–300 词，多镜头 250–450 词，Ref2VA 350–500 词）。为了凑字数加的事件、道具、规则段要删掉；写得太短的段同样要补画面和声音细节。

### 第 1 轮：故事和空间设定

在提示词之外写一张规划表：
- 每段的剧情节拍和戏剧作用，一句"原因 → 动作 → 结果"。
- **空间设定**：每个反复出现的地点，以及地点之间的地理，按 `h3-action-prompt-design` 第 3 节的表记录。项目卡里已有的（如《纸引》大殿）直接用。
- 素材到实体的映射：同一人、同一地点的几张图合成一个主体。
- 每个角色一段固定声线，每段照抄。
- 每段的分镜类型：一打多、一对一冲突、对话、安静戏，决定用哪张骨架和哪个范例。
- 接力图：哪些段 latent 接力，每条链多长，在哪里用只靠参考图生成的一段重建锚点。

### 第 2 轮：逐段重写

每一段：
1. 定分镜类型，**先读 `h3-shot-prompt` 的 `references/examples.md`**（官方改写示例 + 最接近的本地范例；快剪动作看 3.1，多节拍文戏看 3.2），再动笔。
   异能、元素变化、时间静止、御剑和一打多另读 `h3-shot-prompt/references/powers-and-effects.md`：明确的一镜到底不按快动作表强拆；时间静止、集体定身段省去要求全员持续活动的全局表演段，逐人写静止/可动状态。
2. 按 `h3-shot-prompt` 写：按播放顺序的英文描述；镜头数先定戏的类型，再查时长表；官方镜头头和切镜动词，切镜句写景别和运镜状态；后续镜头用 `from Shot N` 复指；每镜一条主动作链，物理写全；状态逐镜陈述；台词标签带空格，说话人收口和听者闭嘴按 skill 的适用范围；最后一秒不开始新动作；`overall_soundscape` 写 2–4 句，关键声音绑到动作上；配乐按项目约定（接力剧集默认 `N/A`）。
3. 挂素材的段用六段式，素材部分按 `h3-action-prompt-design` 第 1 节；空间、门、手、接力按对应章节。
4. 画风底座和角色插句从项目卡照抄，同一场戏的多段用同一句底座和光源。
5. 接力段：本段第一个镜头的起点等于上一段最后一个镜头的实际结束状态，环境句照抄。
6. negativePrompt：工作流没接就留空；接了就写几项和本段相关的。
7. 每段写完跑一次 `lint_json.py`，ERROR 清零。

原来能跑通的段（用户说过效果好的），不整段重写，只改有问题的那一处；要换成新文体，先拿一段做 A/B（`h3-shot-prompt` 的 `pipeline-and-settings.md` 第 5 节），新文体胜出后再批量改。

### 第 3 轮：对白本地化

粤语（细则见 `h3-action-prompt-design` 第 6 节）：
- 标签用 `[Cantonese]`，香港繁体口语字，语气词用对，唔該/多謝分清，数字写"三十"不写"卅"。
- 每个角色有自己的口头禅，两个人不共用，除非有意。
- 每句标说话人和本段编号；两人以上在画时写说话人在画面哪侧；听的人先写反应，闭嘴只在 `h3-shot-prompt` 的三种情况写（切到听者用画外音句；单人说话但画里有别人时写 `… watch silently, their mouths kept firmly closed.`；听者的脸和说话人同时清楚在画里时把闭嘴并进反应句 `…, his lips pressed together.`）。看不到脸的听者、没人说话的镜头不写。
- 用 OpenCC s2hk 查简体残留；它对 借借、晒、諗吓 的报错是误报，原样保留。
- 整集开跑前，每个主要声线先跑一段试口型和发音。

### 第 4 轮：逐项检查

每项单独过一遍全部段落。

| 检查 | 问题 |
|---|---|
| 文体 | 每一句都通过"可观察测试"吗？有没有混进规则段、强调、禁令、标签？ |
| 镜头结构 | 镜头数对得上时长吗？切点在节拍边界上吗？每镜只有一条主动作链吗？切镜句写了景别和运镜状态吗？每个切点都带来新信息吗？原因在画面里看得见、结果在下一镜看得见吗？最后一秒没有新动作吗？ |
| 物理 | 每个接触写了起因、用力、反应、落定吗？有没有两人全身精确接触、快速大幅动作这类 H3 做不好的设计？ |
| 状态 | 火、伤、湿、门、灯、剩余人数有没有逐镜用陈述句写出？有没有无缘无故复位？ |
| 方向 | 每次移动写了上下、里外、哪个出口吗？固定机位和路线符合空间设定吗？对话守住 180 度线了吗？反打重写了左右吗？ |
| 手和道具 | 身体左右和画面左右对得上吗？"空手"其实拿着东西吗？道具跨镜延续吗？人力开门写了人、手、方向、结束位置吗；异能开门写了施力触发、方向、结束位置吗？ |
| 异能 | 能力来源、对象、范围、结果与简报一致吗？发光能力有对应局部光，隐形念力只用指定的物体变化表现吗？静止期间被定住的人有无小动作？人数与武器数量可追踪吗？限定的声音有没有被新增拟音或配乐覆盖？ |
| 背景连贯 | 全景之后的近景，重写了墙、招牌、灯吗？景深适中吗？ |
| 参考状态 | 参考图的灯、门、天色、天气、损坏和剧情此刻一致吗？有挂着却看不见的素材吗（建议禁用）？ |
| 行为 | 每个角色有起点、路线、起因、终点吗？画外角色的方向在整组蒙太奇里一致吗？ |
| 尺度 | 高度、距离合理吗？相隔远的东西景别够宽吗？ |
| 台词 | 字数在预算内吗？超了就标出来建议加长或拆段，不自己改时长。远低于预算（台词不到 24 字、动作又简单）的段，建议并进前后段；但为防串词按说话人拆开的单人段（性别、年龄段、服装相近并且近距离同框的两人，例如钱总和阎王）不建议合并，宁可短（`h3-shot-prompt` 的 `references/performance-and-dialogue.md` 第 2 节）。 |
| 声源 | 每段几个人说话？两人以上时台词隔开了吗？看得见脸的听者写闭嘴了吗（看不到脸的没写）？画内说话人说完写收口了吗？拆成一人一段会不会更稳？ |
| 缺席角色 | 正向里点了不在场角色的名字吗？改成按位置或身份说。 |
| 否定句 | 正向里有"没有 X"吗？改成结束状态、构图或用真东西填空；只留那一句统一的文字防护。 |
| 素材职责 | 每个素材的主体行写了提供什么、不提供什么吗？角色卡的纯色底旁边有场景主体吗？手、鞋、道具特写没挂角色卡吗？关键道具每次出现都写了 `matches <Subject N> exactly` 吗？ |
| 尾巴和长度 | 时间点用的是实际片长吗？最后一秒有允许的余动吗？环境声服从用户的静音或封闭声源限制，没有为填尾巴新加声音吗？ |
| 接力 | 接力段都挂着身份参考吗？有没有从空画面开始的段？长链有没有断点重建锚点？ |
| 表演 | 普通戏人物有合适的小动作吗？时间静止、集体定身按受限姿态检查，未给被定住的人补活动吗？听的人对具体那句话有反应吗？情绪写成微动作，而不是直接说出来吗？ |

### 第 5 轮：重建和校验（每次都用脚本）

- 所有非提示词字段和原文件完全相同。
- 每段的 ref 完全相同、顺序不变。
- 台词和上一版相比没变（对白轮除外）。
- 段落顺序正确，没有残留的占位符。
- `lint_json.py` 没有 ERROR（剩下的 WARN 逐条看过、该报告的报告）：每段镜头数、切点在实际片长以内且递增，台词字数在预算内（超出的已列入待定）。
- 列出这一轮改了哪些段。

### 交付

发新的 JSON，加一段中文说明：
- 按问题类型分组的表：哪些段、改了什么。
- 需要用户决定的事：剧情逻辑的疑点、和场景矛盾的素材、台词超预算的段、建议合并或拆分的段。

### 第 6 轮：出片后复查（用户发来渲染结果时）

- **帧**：抽每段的首、中、尾帧并放大看：多余的手臂、手指数、说话人朝向、结尾有没有人脸出画、表情、道具数、重复的人。第三方实例：只看中间帧，100 段过了 99 段，用户随后在开头结尾和放大后找出 16 处毛病。只看了中间帧就说"中间帧初查"，不说"通过"。
- **长度和剪辑点**：ffprobe 时长对照实际片长；每个剪辑点落在写的时间上吗，有没有两个镜头被并成一个。
- **声音接缝**：同一场戏相邻两段交界处量电平。数字静音，或掉 18 dB 左右以上，说明缺环境声，后期每场铺一条环境底。台词下面不垫有人声的歌。
- **台词**：听字和声线。ASR 只能确认一句说完了，人名和方言它会听错。
- **修改纪律**（和 `h3-shot-prompt` 一致）：
  - 先排除提示词以外的原因：打戏 LoRA 有没有挂、CFG 和步数、时长填得对不对、是否只跑了一个种子（见 `h3-shot-prompt` 的 `pipeline-and-settings.md` 第 3 节）。
  - 一次只改一处，先删后加：先看删掉一个事件、一个镜头能不能解决；要加，就在出问题的镜头里加一句可观察的陈述，这段其他文字一字不动，另存为新版本。不加 `IMPORTANT` / `FORBIDDEN`。
  - 改法先查 `h3-shot-prompt` 的 `references/troubleshooting.md`，再查 `h3-action-prompt-design` 第 11 节。
  - 一段重生成一次后停下来报告，第三次之前先问。建议每轮用不同的种子区间（3101、4101、5101），但 JSON 里的 seed 除非用户要求不改。
  - 保留每一个被替换的版本。整个项目的模型配置保持不变，混用会偏色。

## 4. 构建方法（让每一轮都安全）

- 把重写保存成数据，不手改 JSON：
  - 每段一条记录：画风键、分镜类型、`sum`、`dd`（或 `imd`）、`snd`、`neg`，用 `{AJ}`、`{P1}` 这样的实体标记。
  - 一张实体表：别名 → 实体、定义句、类型（人、场景、道具、文字）。
  - 一个构建器：按 ref 首次出现的顺序把标记换成 `<Subject N>`，拼出六段式或三段式。
- 之后的修改都用精确子串替换，限定在一段的一个字段里，并断言只匹配一次。绝不凭记忆或截断的输出重打整段提示词。
- 双引号包的 Python 字符串里，双引号要转义（`\"7\"`）。
- 标记不在本段实体里时构建器报错；实体在 `detailed_description` 里一次都没提到时报警告。
- **只加一句的修补**：写成插入，挂在出问题镜头里一句唯一的原句后面。校验锚点只出现一次、去掉插入能还原上一版、新文字能通过可观察测试、没有 `<d>` 之外的中文、没有缺席角色、没有本段没挂的道具。改完跑 `lint_json.py`，再读几段完整提示词。

## 5. 用即梦重做场景图和门牌图

用户要重做参考图（比如用 Seedream / 即梦）且保持文件名不变时：

- **顺序**：先做材质母版，再做基于参考的场景板，最后做单项修改。
  - 每个地点的母版纯文字生成，中性状态（能开关的灯都关着）。
  - 标志性场景板以母版（和字形特写）为参考。
  - 状态变体（灯灭、门变墙）是在底图上只改一处，机位保持像素对齐。
  - 编号门牌从一张门牌母版出，只改数字。
- **把空间设定画进图里**：固定机位的左中右各是什么、出口楼梯窗在哪、固定物的真实高度距离、必须固定的唯一道具（那张凳子）。
- **提示词结构**（即梦用中文）：`【场景】【构图】（左/中/右）【光线】【细节】`，结尾一句排除项（无人物、无水印、无多余可读文字），因为即梦没有负向栏。画面文字用引号逐字写、写短；老是写错字就出空白版，文字后期排上去。
- **交一个 Excel**：
  - `说明`：设置和保存规则。
  - `重做提示词`：顺序、文件名（不改）、路径、类别、比例、做法、按上传顺序的参考图（图1/图2）、提示词、用在哪些段、文字要求、验收项，外加一列黄色的待确认项。
  - `空间设定`：每个地点的空间设定，不只是主场景。
  - `素材总表`：全部素材，带一个统计用在几段的公式。
- **保存**：先备份原图，再用同名 PNG 覆盖原路径。fingerprint 会变，提醒用户在导播台里重新扫描或导入。
- **角色和道具卡**（用户也要重做时）：
  - 角色：16:9 三联卡，中性底，正面全身、背面全身、半身。全身格可以裁掉头，让整张卡只有一张脸。
  - 服装：白底正反面，印字清楚。
  - 车辆：外观几个角度加细节（把手、轮子、灯）和内饰。
  - 地点：空场景，光线和剧情此刻一致。
  - 每张卡的纯色底都可能带进场景，用卡的段同时要挂场景主体。

## 6. 讲解一段戏

用户问某段怎么演时，用中文按这个顺序答：
1. 它在故事里的作用（包括它兑现的规矩或伏笔）。
2. 逐个镜头：位置、动作、台词、结束状态。
3. 运镜和声音。
4. 表演意图：情绪是什么、不是什么。
5. 生成时要盯的风险：文字、重复的人、台词密度、方向。
